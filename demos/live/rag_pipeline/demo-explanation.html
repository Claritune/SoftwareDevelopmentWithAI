How the RAG demo works

A fully local Retrieval-Augmented Generation pipeline over Alice’s Adventures in Wonderland. Nothing leaves the laptop. Ollama runs the models and ChromaDB stores the vectors, both on your machine.

1Loadread the book 2Chunksplit into pieces 3Embedtext → vectors 4Storesave in ChromaDB 5Retrieve & answersearch + LLM
Indexing (steps 1–4)Done once per book. Turns raw text into a searchable store of meaning-vectors.
Querying (step 5)Done per question. Finds the most relevant passages and has the LLM answer only from them.

Why RAG?

An LLM only knows what was in its training data, and it can confidently make things up. RAG fixes that by looking up relevant passages from your documents first, then handing them to the model as context. Answers become grounded in a specific source you can cite and check.

Without RAG

“What did the Hatter say about time?” → the model answers from fuzzy memory of the book, with no sources and possibly invented quotes.

With RAG

The same question → the 4 most relevant tea-party passages are retrieved → the model answers from those passages and cites books/alice.txt.

2

Split into chunks

A whole book is far too big to embed as one vector, or to paste into a prompt. So it is cut into small, overlapping chunks. Each chunk becomes one unit of search. RecursiveCharacterTextSplitter prefers to split at paragraph breaks, then lines, then spaces. That keeps sentences intact where it can.

Trade-off. Smaller chunks give more precise retrieval but less context per hit. Bigger chunks are the reverse. demo.py uses 500/80 to show many small, focused passages. rag_pipeline.py uses 1000/200 for whole libraries.
3

Generate embeddings

Each chunk is sent to the nomic-embed-text model running in Ollama, which returns a list of 768 numbers, its embedding. Think of it as a coordinate in a 768-dimensional “meaning space”. Texts about similar things land close together, even if they share no words.

r = httpx.post(f"{OLLAMA_URL}/api/embeddings",
               json={"model": "nomic-embed-text", "prompt": chunk_text})
vector = r.json()["embedding"]          # → [0.0123, -0.4410, 0.2871, …]  (768 floats)
Why one-at-a-time? The custom OllamaEmbeddings class embeds chunks one request at a time. Batch requests can fail with encoder-only models like nomic-embed-text in Ollama, and the per-chunk progress counter looks good on stage anyway.
4

Store in ChromaDB

The chunks and the vectors from step 3 are written together into a ChromaDB collection on disk at ./chroma_db_alice. ChromaDB runs embedded, inside the Python process, so there is no server to start. It builds an HNSW index over the vectors, a graph that finds nearest neighbours quickly without comparing against every vector.

Fresh every run. demo.py deletes and rebuilds the collection each time, so rehearsals always start clean. The folder is gitignored.
5

Semantic search + LLM answer

5a · Retrieve

The question is embedded with the same model, placing it in the same meaning space as the chunks. ChromaDB then returns the k = 4 chunks whose vectors are closest to the question’s vector.

Real retrieval from a demo run for “What did the Mad Hatter say about time at the tea party?”:

#1'Well, I'd hardly finished the first verse,' said the Hatter, 'when the Queen jumped up and bawled out, "He's murdering the time! Off with his head!"'…
#2'Of course you don't!' the Hatter said, tossing his head contemptuously. 'I dare say you never even spoke to Time!'…
#3The Hatter shook his head mournfully. 'Not I!' he replied. 'We quarrelled last March—just before HE went mad, you know—'…
#4'Yes, that's it,' said the Hatter with a sigh: 'it's always tea-time, and we've no time to wash the things between whiles.'…

The book never uses the phrase “Mad Hatter”. He is always just “the Hatter”. These passages were found by meaning, not keyword matching.

5b · Generate

The four chunks are pasted into a prompt template along with the question, and sent to llama3.1:8b with temperature=0 for repeatable output. The instruction tells it to answer only from the context.

instruction
Use ONLY the context below to answer the question.

The Mad Hatter said that “He’s murdering the time!” when referring to Time (the person) and also mentioned that it was always six o’clock now, implying that time had become distorted or stuck. He also mentioned that he and Time quarrelled before Time went mad.
Sources: books/alice.txt
chain = (
    RunnableParallel(context=retriever, question=RunnablePassthrough())   # 5a: fetch top-k
    | RunnablePassthrough.assign(result=prompt | llm | StrOutputParser()) # 5b: answer
)
response = chain.invoke(query)   # → {"context": [Document…], "question": …, "result": "…"}

The chain keeps the retrieved context documents in its output. That’s how the demo prints the sources next to the answer.

Two ways to run it

Guided walkthrough

One book, every step shown, pauses for ENTER. Best for presenting.

uv run python demo.py
Ingest + interactive Q&A

Any number of books in books/, then ask your own questions.

uv run python rag_pipeline.py
uv run python interactive.py

Run from demos/live/rag_pipeline/. Needs ollama serve running with nomic-embed-text and llama3.1:8b pulled.
